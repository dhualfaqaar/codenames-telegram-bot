# التشغيل تحت الضغط وحصة الخطة المجانية

حصة Cloudflare تشمل الحساب كله، مو هذا البوت وحده. `100,000` كتابة صف يومياً ليست عدد مستخدمي تيليجرام، وطلبات Workers وDurable Objects لها حدود مستقلة. راجع [التسعير الرسمي](https://developers.cloudflare.com/durable-objects/platform/pricing/) و[حدود Workers](https://developers.cloudflare.com/workers/platform/limits/). ماكو ضمان أن الخدمة المجانية تكفي 100,000 مستخدم نشط أو ضغطاً متزامناً كبيراً.

النسخة الحالية تتفادى حفظ حالة البوت عند منشور قناة تم تجاهله، ولا تحفظ الحالة عند فحص متابعة الفرق إذا ماكو متابعة فعّالة. الحالات المتغيرة تبقى تنحفظ، ويُعاد طلب الحفظ عند فشل كتابة سابق ضمن نفس دورة حياة الكائن. هذا ما يعني أن كل الرسائل مجانية أو بلا كتابات، وما يحمي البيانات من فقدان كتابة فاشلة عند توقف الكائن قبل المحاولة التالية.

الاستيراد الجماعي للقناة يبقى متوقفاً؛ لا يُستأنف إلى أن نقيس تكلفة FTS ونبني استيراداً محدوداً وقابلاً للاستئناف. لم نقس استهلاك الحساب الفعلي أو نختبر 100,000 مستخدم على الإنتاج. بعد تجدد الحصة، قارن استخدام الحساب وMetrics لكل namespace بالأوقات نفسها، ثم نفذ اختبار حمل تدريجي خارج الإنتاج بسيناريوهات ألعاب وبحث واقعية، وراقب الأخطاء والكمون والكتابات والذاكرة والحدود.

معظم تحديثات تيليجرام وحالة البوت ما زالت تستخدم Durable Object واحداً باسم `main`، وهذا اختناق محتمل. عند أول حفظ ناجح بعد التحديث، تنقل الحالة القديمة في معاملة ذرّية: سجلات المستخدمين والمحادثات بصفحات 128 سجلاً، والحقول الباقية بمفاتيح منفصلة. الذاكرة المؤقتة تقارن الصفحات الآمنة وتكتب المتغيّرة فقط؛ القيم غير القابلة للمقارنة الآمنة تُكتب احتياطياً. المفتاح القديم `state` يُترك دون حذف كنسخة قبل النقل، لكنه يصبح **قديماً** بعد النقل، وليس نسخة احتياطية محدثة. التراجع إلى كود أقدم يقرأه قد يفقد التغييرات اللاحقة، فلا يتم دون خطة ترحيل عكسي موثوقة. عند فشل النقل تتراجع المعاملة كاملة وتبقى النسخة الأصلية؛ وعند تعذر قراءة جزء من النسخة الجديدة يتوقف الاسترجاع بأمان بدلاً من استخدام النسخة القديمة بصمت.

لا يزال كل حقل بمفرده وكل صفحة خاضعين لحد الحجم، ويبقى تحميل كامل الحالة ومقارنة الصفحات على الكائن الوحيد غير مصممين لضمان تحمّل 100,000 مستخدم نشط. يلزم لاحقاً عزل المستخدمين والغرف وتوزيع الحمل واختبار الترحيل والاستعادة بصورة أوسع. إنشاء كائنات أخرى لا يرفع الحصة اليومية المشتركة للحساب. راجع [حدود Cloudflare](https://developers.cloudflare.com/durable-objects/platform/limits/). إرسال webhook الحالي يؤكد الاستلام قبل اكتمال معالجة التحديث، لذا فإعادة المحاولة وضمان عدم ضياع التحديثات عند الأعطال تحتاج تصميم مستقل، وليست مضمونة هنا.
